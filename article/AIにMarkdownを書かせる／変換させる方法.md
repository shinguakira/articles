# AIにMarkdownを書かせる／変換させる方法

## プロンプト
生のMarkdownで出力。4つのバックティック（````markdown）で囲んだ一つのブロック内に書いて。内部のコードブロックは3つのバックティック(```)使って。
## 背景
AIに「書いてほしい内容」をそのままGitHub IssueやQiitaに貼り付けられるMarkdownとして出力させたいのに、余計な前置きや説明が入って使いづらい、あるいは構造化されていないという課題がよくある。特に**内部にコードブロックが含まれる場合**、構造が壊れて失敗することが多いため、これを防ぐにはプロンプトの設計を工夫し、「出力形式」を厳密に指定することがキーになる。

## 失敗しがちなケースと理由（特に内部にコードブロックがある場合）
- **外側に三つのバックティックだけを使っていて、内部にも同じ ``` を使うと、Markdownパーサが「ここでブロックが閉じた」と誤認識して構造が壊れる。**  
  → 内部のコードブロックが外側を早期に閉じてしまい、以降の内容が意図せず通常テキストになったり、途中で切れたりする。

- **指示が曖昧で「余計な説明を入れない」ことを明確に書いていないと、AIが補完しようとして前置き・解説・注釈を勝手に入れてしまう。**  
  → 結果として生のMarkdownではなく、不要な自然言語が混じる。

- **外側と内側でバックティックの数が同じだと境界があいまいになり、ネストされたコード構造が崩れる。**  
  → 解決策としては外側を4つ（````markdown）にして、内部を3つ（```）にすることで衝突を避ける。

- **「出力はMarkdownのみ」と明示していないと、AIが説明/注釈付きで出力し、コピー＆ペースト先で意図した表示にならない。**

### 失敗例（よくある出力の破綻）
以下のように **外側も内側も三つのバックティックで囲った** 指示／出力だと、構造が途中で切れたり、余計な説明が入ったりすることがある：

```markdown
# タイトル

## コード例
```python
print("hello")
```
このあと本来続けたかった内容が、外側のブロックが閉じられてしまってMarkdownとして壊れる、あるいは余計な説明が入る。

### 成功例（正しいラッピング）
外側を **四つのバックティック（````markdown）** にして内部を三つにすることで、ネストされたコードブロックが壊れず、余計な説明も入らない：
````markdown

（↑上記は内部の ```python``` が外側の ``` を閉じたと解釈されて以降が不安定になる典型的な失敗例）


````markdown
# タイトル

## コード例
```python
print("hello")
```
このあと本来続けたかった内容が、外側のブロックが閉じられてしまってMarkdownとして壊れない、あるいは余計な説明もない。
````
## 補足
この構造だと内部のコードブロックが外側を壊さない。
